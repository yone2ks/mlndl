# ADR-0021: `link_speed` の書式

- **Status**: Accepted (2026-11-07 に実装)
- **Date**: 2026-11-07
- **Deciders**: mlndl-spec-architect, mlndl-linguist, mlndl-dsl-designer, network-tech-reviewer, mlndl-example-author、ユーザー
- **Pass**: C (5 エージェントの検討を 2 回行った。下書きはない)
- **関連**: ADR-0003 / ADR-0009 (注釈側の構成子)、ADR-0006 (無向のリンク)、ADR-0011 D3 (書かれたまま保持する)、ADR-0017 D4 (契約帯域は `description`)、
  ADR-0020 (L1 リンクの `mtu` をなくした)、[先送りした項目](deferred.md)

## Context

`layer1.links[].link_speed` は書式の決まっていない文字列だった。リポジトリの値はすべて `<整数>G` (`10G` / `1G` / `100G` / `40G` の 118 件) だが、
`10Gbps` / `10000` / `10 G` のどれを書いても通り、ツールは値を比べられない。1.0 のリリース後に書式を決めると、書いた YAML が通らなくなる。

ユーザーの問い:

- `10Gbps` がイメージに近いが、1Tbps を `1000Gbps` と書いてもよいのか
- `10000` と数字だけ書くのもよいが、800Gbps を `800000` と書くのは大変すぎる
- 数字で書いても、ndl-viz では見やすい書き方に直す必要がある
- 10bps のような遅いリンクや、`T` の次の単位はどうなるのか

## Decision

### D1. `<数値><単位>` の文字列で書く

```yaml
link_speed: 10G      # 10 Gbps
link_speed: 2.5G     # NBASE-T
link_speed: 1.6T     # 1.6 Tbps
link_speed: 1.544M   # T1
link_speed: 64K      # ISDN の B チャネル
```

- **単位**は `K` / `M` / `G` / `T` のどれか 1 文字で、大文字だけ。`bps` は付けない
- **値は 10 進のビット毎秒**。`K` = 10³、`M` = 10⁶、`G` = 10⁹、`T` = 10¹² bps。1024 倍 (KiB など) ではなく、バイトでもない
- **数値**は整数か小数で、小数の桁数は制限しない (T1 `1.544M`、E1 `2.048M`、OC-3 `155.52M`、OC-192 `9.95328G` が実在する)
- **数値の形**: 整数部は必須で、先頭に余分な `0` を付けない (`01G` は不可、`0.5G` は可)。小数点を書くなら小数部も書く (`10.G` は不可)。0 より大きい
- 引用符は要らない。YAML は `2.5G` も文字列として読む

**キロを大文字 `K` にする理由**: SI ではキロだけが小文字 `k` だが、`k` を許すと「`g` は不可で `k` は可」となり迷わせる。
ネットワークの速度は `64K` と大文字で書く慣習も強い。単位はすべて大文字にそろえる。

**`K` を入れる理由**: 1M 未満の回線が実在する (ISDN 64K / 128K、シリアル専用線 9.6K〜64K)。EVE-NG のラボで Cisco のシリアル IF を使うのも普通である。
`K` があれば、それより遅い速度は書く場面がない (書くなら `0.3K`)。

**`P` 以上を入れない理由**: Ethernet は 1.6T を標準化中 (IEEE 802.3dj)、3.2T はロードマップの段階で、1 本のリンクが Pbps に届く見込みはない。
受け付ける単位を後から足すのは加算的変更で、既存の YAML を壊さない。必要になったら足す。

### D2. 書式に合わない値は error にし、直し方を示す

| 書いたもの | メッセージで示す直し方 |
|---|---|
| `10g`、`64k` (小文字) | `10G`、`64K` |
| `10Gbps`、`10 G`、`10Gb` (`bps` や空白) | `10G` |
| `10GB`、`10GBps` (バイト) | B はバイト。単位はビット毎秒の K / M / G / T だけ |
| `10000`、`10` (単位なし。YAML の数値も含む) | 単位が要る。値を推測しない (Mbps か Kbps か分からない) |
| `.5G`、`10.G`、`01G` | `0.5G`、`10G`、`1G` |
| `0G`、`-10G`、`1e3G` | 0 より大きい `<数値><単位>`（単位は K / M / G / T） |

`link_speed` は `role` / `labels` / `link_role` のような注釈側の構成子 (ADR-0003 / ADR-0009。コアは値を見ない) ではない。
両端で同じ値になる物理量 (ADR-0020) なので、コアが書式を検査する。

### D3. 同じ値の別の書き方は warning にする (書き換えない)

正規形は「**数値が 1 以上 1000 未満になる単位で書き、余分な 0 を付けない**」。ただし `T` より上、`K` より下へはずらさない。

| 書いたもの | 正規形 |
|---|---|
| `1000G` | `1T` |
| `2500M` | `2.5G` |
| `2048K` | `2.048M` |
| `0.5G` | `500M` |
| `0.064M` | `64K` |
| `10.0G`、`1.5440M` | `10G`、`1.544M` |
| `1.544M`、`9.6K`、`800G`、`1.6T` | そのまま (warning なし) |
| `0.3K`、`1200T` | そのまま (端の単位より先へはずらさない) |

- warning は書き手への助言で、mlndl は表記を書き換えない。YAML エクスポーターも書かれたまま出す (ADR-0011 D3 と同じ考え)
- 判定は Decimal で行い、浮動小数点の誤差を出さない

### D4. 数値への変換はまだ足さない

ndl-viz は `10G` をそのまま表示すれば読めるので、変換は要らない。速度を比べる検査 (LAG のメンバーの速度がそろっているか等) や、
速度で線の太さを変える表示が要るようになったら、mlndl に数値 (bps) に直す関数を足し、エクスポーターから数値も出す。

### D5. ADR-0020 の言い方を直す

ADR-0020 は `link_speed` を「両端の交渉で同じ値に決まる」と書いた。シリアル回線は交渉ではなく DCE 側のクロックで決まるが、
上がったリンクの速度が両端で同じである点は変わらない。「両端で同じ値になる媒体の性質」と読み替える。

## Consequences

**良い影響:**

- 同じ速度の書き方が 1 つにそろい、検索や LAG の束のラベル (`×2 10G`) がばらつかない
- 今ある 118 件の値は書き換えずに通る
- 将来、速度を比べる検査を足すときに、値の読み方が決まっている

**悪い影響 / トレードオフ:**

- `10Gbps` のように書き慣れた形が error になる (メッセージで直し方を示す)
- 正規形の warning が、回線の契約での書き方の慣習 (`0.5G` など) を上書きするように感じられることがある。
  warning であって error ではなく、表記は書き換えないことを言語リファレンスに明記する (mlndl-dsl-designer の少数意見)

**影響を受けるコンポーネント:**

- スキーマ: `src/mlndl/schema/layer1.py` (`L1Link.link_speed` の検査と、正規形を求める関数)
- バリデーター: `src/mlndl/validator.py` (正規形の warning)
- 文書: `docs/reference/`、`CLAUDE.md`

## Alternatives Considered

- **`<数値><K|M|G|T>` の文字列** *(採用案)*
- **`bps` 付き (`10Gbps`)**: 意味は一番はっきりするが、全リンクで 3 文字ずつ増え、今の 118 件を書き換えることになる。フィールド名 `link_speed` で、`G` がギガビット毎秒であることは文脈で決まる
- **整数 (Mbps)**: 機械には扱いやすいが、`800000` と `1600000` が並ぶと桁を数え間違える (試し書きで全行にコメントを付けたくなった)。単位が見えず、NetBox の Kbps と取り違えやすい
- **文字列と整数の両方を受ける**: 同じ値の書き方が 2 系統になり、`1G` と `1000` が並ぶ
- **`{value: 10, unit: G}` の構造**: 10 文字で済む情報に 2 行使う
- **推奨値の列挙 (enum。OpenConfig の `SPEED_10GB` など)**: 新しい速度が出るたびに言語を直すことになる
- **`1000G` と `1T` の両方を正規とする (warning なし)**: mlndl-dsl-designer の 1 回目の意見。ほかの 4 人は、書き方がばらつく実害 (検索・LAG の束のラベル) から warning を推した
