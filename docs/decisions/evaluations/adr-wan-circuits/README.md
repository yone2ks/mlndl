# ADR-wan-circuits — WAN 回線の表現 試し書き

対象: `L1Link` に属性を足す / 独立エンティティ `layer1.circuits` / 網を箱ノード / 使い分け
の 4 候補を、WAN の典型シナリオ 5 本で書き分ける。

- 前提: サイトは `labels: {site: ...}` で表す (ADR-site-boundary 評価の結論)
- 「書けるか」の列は、候補ごとの構文で **自然に書けるか** を見る (現行スキーマで
  parse できるかどうかは別の列)

## 候補

| 記号 | 内容 | 現行で parse できるか |
|------|------|----------------------|
| A | `L1Link` に `provider` / `circuit_id` / `service` / `bandwidth` を足す | **できない** (L1Link は `extra="forbid"`。新フィールドの追加は未実装) |
| B | `layer1.circuits:` を独立エンティティにし、`L1Link` が `attaches_to: {circuit: ...}` で参照 | **できない** (新コレクション + `attaches_to` キー追加が未実装) |
| C | 網を箱ノードで表現 (`role: provider-network` / `role: internet` / `role: dx-connection`) | **できる** (ノード・IF・リンク・labels・attaches_to だけで書ける) |
| D | 専用線 = リンク + 属性 (A)、網 = 箱ノード (C) の使い分け | A 相当部分は不可、C 相当部分は可 |

## シナリオ

| # | 概要 | 全候補書くか |
|---|------|-------------|
| S1 | 東京 DC と大阪 DC を 2 本の専用線で冗長 (事業者別、回線 ID あり) | 全候補 |
| S2 | 3 拠点を IP-VPN。CE は PE と eBGP。対向拠点は L3 で見えない | 差分のみ |
| S3 | 3 拠点を広域イーサで接続。同一 VLAN がストレッチ | 差分のみ |
| S4 | 本社がインターネット回線 2 本。ISP はトポロジー外。支社とは GRE/IPsec | 差分のみ |
| S5 | オンプレとクラウドを閉域接続 (Direct Connect 等)。ADR-0008 `role: vpc` 参照 | 差分のみ |

## 評価軸

各候補のファイル先頭に以下を書く:

1. 種別 (service) を書けるか
2. 事業者 (provider) を書けるか
3. 回線 ID (circuit_id) を書けるか
4. 帯域 (bandwidth) を書けるか
5. 片端がトポロジー外 (ISP、クラウド事業者側 PE 等) の回線を書けるか
6. VLAN / L3 IF / BGP セッションの通り道 (ADR-0010 D7 の導出) とどうつながるか
7. ndl-viz でどう見えるとよいか (線か雲か、ラベルに何を出すか)

## 回答概要 (ファイル全体を読んだ後の総合判定)

- **A はシンプルだが片端外相手を書けない**: 回線 ID や帯域はリンクに書くのが素直 (他の L1Link 属性 `link_speed` / `mtu` と並列)。だが IP-VPN / インターネット / Direct Connect のように対向が見えない場合は L1Link の両端を L1 IF にしていると書けなくなる (`endpoints: Ref("layer1.interfaces")`)。
- **B は中継リンクが共有回線の上を走る場合に強い**: 一本の物理回線上に複数の論理リンク (VLAN 分け等) を乗せるケースを素直に書けるが、Phase 1 範囲では過剰。
- **C はほぼ全部書ける**: 「網も箱」で済ませられ、ADR-0008 の `role: vpc` と対称。属性の受け皿は `labels` に逃がすしかない (`labels: {provider: ..., circuit_id: ..., service: ...}`)。意味論的には **分類 (Classification)** ではなく **固有識別** を labels に書くことになり、ADR-0009 D1 の意味論と衝突する。
- **D (使い分け) が実用上は最も素直**: 片端外相手を書く必要があるかどうかで A と C が自然に住み分ける。ただし「IP-VPN は網だが L2 専用線は線」の線引きが筆者判断に残り、同じ物理媒体 (ダークファイバ上の L2 専用線 vs. 広域イーサ) で揺れる。
